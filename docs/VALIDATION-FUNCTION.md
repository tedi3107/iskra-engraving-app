# Engraving validation function

`extensions/engraving-validation` re-checks each engraved cart line at checkout
against its product's zone (Position designer): **Max characters** and
**Uppercase only**. The storefront already enforces both while typing; this
catches orders that bypass it (anyone can call `/cart/add.js` directly).

- Target: `cart.validations.generate.run` (API 2026-07)
- Input: each line's `Engraving` attribute + the product's
  `engraving.zone` metafield (`src/cart_validations_generate_run.graphql`)
- Output: one `validationAdd` with cart-level (`$.cart`) error messages
- Fails open (`blockOnFailure: false`): if the function itself errors,
  checkout proceeds.
- Activation: automatic for new installs (`afterAuth`), and manual on the
  Setup page. Needs the `write_validations` scope.

## Before the first deploy (one time)

The function's GraphQL schema is generated by the Shopify CLI and needs your
login, so it's not committed yet:

```sh
shopify app function schema --path extensions/engraving-validation
```

That writes `extensions/engraving-validation/schema.graphql`. Commit it. Then
the integration tests (which run the built `.wasm`) work:

```sh
cd extensions/engraving-validation && npx vitest run
```

## Rolling out to an existing store

1. Deploy (`shopify app deploy`). `write_validations` (and `read_orders`) are
   new scopes, so the merchant sees an "Update app permissions" screen the next
   time they open the app. One click.
2. Existing installs don't re-run `afterAuth`. After approving, open
   **Setup** in the app and click **Activate engraving check**. The home page
   shows the status.
3. Test: add an engraved item, then try to check out with text longer than
   the product allows (e.g. via `/cart/add.js`). Checkout should show the
   error.
